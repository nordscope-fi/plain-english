# Copilot advisory control, 8 October 2026

The generated hook returned `ask` for an advisory document finding. Copilot
1.0.80's non-interactive run refused the write because there was no person to
answer. The clean and excluded controls confirmed that the fixture could write.

The repaired adapter returns no refusal before an advisory tool call. After the
tool succeeds, it emits `additionalContext`. Strict checks still return `deny`
before the call runs. Both the original failure and the repaired behavior were
repeated in fresh disposable projects.

| Build and control | File result | Hook result |
|---|---|---|
| 1.12.0 advisory | Unchanged | Pre-tool `ask` |
| 1.12.1 strict bad text | Unchanged | Pre-tool `deny` |
| 1.12.1 strict clean text | Requested text | No finding |
| 1.12.1 excluded bad text | Requested text | No finding |
| 1.12.1 advisory bad text | Requested text | Post-tool context |

The [observation record](observations.json) retains event names, tool names,
field names, decisions, file outcomes, timing and hashes. It omits raw payloads,
responses, identity and account values. Metadata tracers wrap each generated
command and return its output unchanged. Matchers are generated by initialization.
An unconditional tracer separates absent events from clean checks. Each project
starts fresh, so a previous tracer cannot become another installed hook.

The CLI used prompt mode with repository-hook opt-in, automatic tool approval,
custom instructions disabled and built-in remote tool servers disabled. Each
control requested one synthetic file write. Pattern enforcement remained active;
real model judges were disabled. The CLI chose its model through `auto`.

This record covers native document edits. Automated tests cover shell and issue
advice, explicit legacy user installation and optional model-call counts. Hosted
cloud execution remains unverified. Re-run initialization after upgrading to
install the new post hooks.

[GitHub's reference](https://docs.github.com/en/copilot/reference/hooks-reference)
documents context after successful tool calls. Its permission-question option
depends on an interactive answer. The live control determines the prompt-mode
behavior recorded here.
