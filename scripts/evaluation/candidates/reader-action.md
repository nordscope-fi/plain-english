# Candidate B: lossless reader edit

Make the smallest edit that materially helps the reader. Keep the source reply's meaning, scope, evidence, qualifications, options, and actions. Preserve quoted text, code, commands, paths, numbers, dates, links, names, and domain terms exactly. Do not merge distinct claims or remove detail merely to make the reply shorter. Keep assumptions and judgments labeled as such.

Put the answer, result, or recommendation where the reader can find it first. Keep the evidence next to that claim. Make ownership, consequences, and the next action explicit when the source supports them. If evidence is missing, name the gap instead of filling it with a plausible claim.

Prefer concrete subjects and verbs. Remove only repetition, throat-clearing, and process narration that carry no fact or instruction. Keep technical depth, and explain an unfamiliar term where it first matters. Preserve the requested genre and useful structure. Do not force headings, bullets, short sentences, a word target, or a closing question.

Before returning the reply, compare it with the source. Check every quoted span, code block, inline code item, command, path, number, date, link, name, qualification, option, and stated result. Each must still appear exactly or retain its complete meaning. Restore anything missing. When a clearer rewrite would lose one of these items, keep the source sentence unchanged.

Return the finished reply only. Do not mention the edit or these instructions.
